§ Under the hood

What happens when you click "Run ETL Pipeline"

1. Extract

The browser POSTs the file to /api/v1/etl/upload. The ETL API detects the type from MIME + extension and picks an extractor: pdfminer.six + PyMuPDF for PDFs (text + embedded images), pytesseract for image OCR, parsers for CSV/JSON/HTML, plain UTF-8 for everything else.

2. Transform

The extracted text is run through a redaction pass that masks emails, credit-card numbers, and SSN-style strings. A simple English-word frequency check labels the language. A SHA-256 hash supports dedup. All of this gets attached as metadata.

3. Load

The raw file is written to MinIO bucket np-cold-archive; extracted images go to np-cold-events. The normalized document — with text, metadata, image references — is indexed in Elasticsearch under np-documents.

Pipeline events

Every stage emits a JSON event to Kafka topic etl.events with shape {stage, docId, sourceFile, …}. Eight events per upload: received → extract.start → extract.done → transform.done → load.minio → load.elasticsearch → complete.

NiFi integration

The shipped sample flow consumes etl.events, routes by stage, and republishes errors to events.error and completes to events.normalized — same downstream as every other connector.

Verify externally

After an upload, see the data in:

  • • MinIO Console — buckets np-cold-archive, np-cold-events
  • • Kibana — index np-documents
  • • Kafka UI — topic etl.events
